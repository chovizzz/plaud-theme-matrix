# 可复核的测试用例格式

**何时读我**：判定 `SelfTestReportStatus`，或有人问"这条用例算不算写清楚了"。

DTC §四 原文：

> 测试用例要写成可复核的形式：前置条件（具体站点 + 主题 ID + 配置状态）→ 操作步骤（给具体 URL）→ 预期结果（具体值或现象）→ 结论。
> **"显示正常""功能可用"不算有效预期结果，这类用例视同未测。**

「可复核」的定义：**另一个人拿着这条用例，不问作者任何问题，能独立跑一遍并得出相同结论。**

---

## 四段式

| 段 | 必须包含 | 判 `Incomplete` 的写法 |
|---|---|---|
| **前置条件** | 具体站点 + 主题 ID + 配置状态（哪些字段填了什么） | "在测试环境""配置好之后" |
| **操作步骤** | 具体 URL + 逐步动作 | "打开页面看一下""正常操作" |
| **预期结果** | **具体值或现象** | "显示正常""功能可用""无异常""符合设计稿" |
| **结论** | Pass / Fail + 附件截图或视频 | 只写 Pass 无附件 |

---

## 合格与不合格对照

### ❌ 不合格

```
1. 测试轮播功能 —— 正常
2. 测试移动端 —— 显示正常
3. 测试多语言 —— 功能可用
```

三条全部视同未测：没有前置条件、没有 URL、预期结果是三个禁用词。

### ✅ 合格

```
用例 3：区头移动端左对齐

前置条件：
  站点 plaud-us / 主题 ID 123456789
  模块 Multi Content - WW 实例 ar7fJC
  header_align_mb = "left"，pre_heading 非空、sub_heading 留空

操作步骤：
  1. 打开 https://plaud-us.myshopify.com/products/note-pro?preview_theme_id=123456789
  2. DevTools 设视口宽 375px
  3. 定位 .cs-section-header

预期结果：
  Pre Heading 与 Heading 均左对齐（computed text-align = left）
  Heading 字号 32px、行高 1.2
  Sub Heading 不渲染（DOM 里无该元素，非空 wrapper）

实际结果：与预期一致
结论：Pass
附件：case3-375-left.png
```

---

## 三个高频不合格点

### 1. 预期结果写成"和设计稿一致"

设计稿一致**不是可复核的预期**——复核人得先找到设计稿、还得知道看哪个节点。要写出**从稿里读出来的具体值**：「Heading 32px / 行高 1.2 / 左对齐」。

例外：确实只能靠视觉比对的（如渐变观感），此时附上设计稿截图与实现截图的**并排对比**，并标出比对的具体区域。

### 2. 前置条件缺「配置状态」

同一个 section 在不同存值下行为不同。只写站点和主题 ID、不写字段填了什么，复核人复现不出来。

**空配置与满配置要各有用例**（与 QA-B 的双测呼应）：字段全空时不崩、字段全填时不溢出。

### 3. 结论没有附件

DTC 原文：**测试结果必须有附件截图/视频**。纯文字结论判 `Incomplete`，不论写得多详细。

动效、交互、多步流程用**视频**；静态样式用截图。

---

## 覆盖面的最低要求

不是「有几条用例」，而是这几类各要有：

| 类别 | 说明 |
|---|---|
| 主路径 | 该改动的核心功能，正常输入 |
| 空配置 | 所有可选字段留空——不得崩、不得输出空壳 DOM |
| 满配置 | 所有字段填满、填长文案——不得溢出裁切 |
| 多语言 | 至少一个长语言（德语）—— 与 QA 的 `LocalizationCheck` 同一组素材 |
| 断点 | 与 8 张截图对应的关键断点行为 |
| 回归 | 若本次是返工或修 bug：**对应的回归用例**（DTC §五：每个线上 bug 反推一条用例入库） |

缺「空配置」这一类是最常见的漏项——运营留空字段导致的线上问题占比很高。
