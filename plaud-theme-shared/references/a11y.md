# A11y — 无障碍底线与判定方法

**何时读我**：做无障碍审计、改交互控件（按钮 / 弹窗 / 轮播 / 表单）、或 QA 跑 `A11yCheck` 时。

> 红线正文（"A11y 底线：button 语义、aria-label、dialog trapFocus、轮播 button + aria-label、对比度 ≥ 4.5:1、skip link、focus-visible"）在 `handoff-schema.md` §8.5。
> **本文是这 7 条的判定细则**——每条给出可执行的检查方法。只列名词不给判法的审计一律记 `Blocked`，不得记 `Passed`。

---

## 1. button 语义

**判定对象**（`handoff-schema.md` §8.5）：可点击、会触发动作的元素必须是 `<button>`（或 `<a>` 用于导航）。不得用 `<div>` / `<span>` + `onclick` 冒充。

| 判定 | 方法 |
|---|---|
| 静态 | `grep -nE '<(div\|span)[^>]*(onclick\|@click\|data-action)' <files>` —— 有命中即 `Failed` |
| 静态 | `grep -nE 'addEventListener\(.click.' <js>` 后回查绑定目标的标签名 |
| 运行时 | DevTools 里对每个可交互元素查 `el.tagName`；`DIV` / `SPAN` 即不合格 |
| 键盘 | 只用 Tab + Enter / Space 操作整个 section，能触达并触发每一个动作 |
| 补救 | 无法改标签时必须补 `role="button"` + `tabindex="0"` + Enter/Space 键盘处理，三者缺一不算合格 |

附加：`<button>` 在表单内要显式写 `type="button"`（否则默认 `submit`，会误提交）。

## 2. aria-label

**判定对象**（`handoff-schema.md` §8.5）：无可见文字的控件（图标按钮、关闭叉、轮播箭头、汉堡菜单、播放键、数量加减）必须有可访问名。

| 判定 | 方法 |
|---|---|
| 静态 | `grep -nE '<button(?![^>]*aria-label)' <files>` 后人工筛出"内部只有 `<svg>` / `<use>` 无文本"的；这些必须有 `aria-label` |
| 运行时 | DevTools → Accessibility 面板 → 该元素的 **Computed name 不得为空** |
| 文案 | `aria-label` 是**展示文案**，同样受 i18n 规则约束——必须走 locales `| t` 或 schema 字段，**不得硬编码英文**（见 `liquid-schema-format.md` §1） |
| 常见漏项 | 关闭按钮、轮播 prev/next、分页点、语言/货币切换器、放大镜、数量 +/- |

`aria-label` 与可见文字**二选一**：已有可见文字的按钮不要再加 `aria-label`（会覆盖可见名，读屏与视觉不一致）。

## 3. dialog trapFocus

**判定对象**（`handoff-schema.md` §8.5）：弹窗 / drawer / modal 打开后焦点被限制在弹层内；关闭后焦点归还触发元素。

| 判定 | 方法 |
|---|---|
| 代码 | 该组件是否继承 `PopupBase` 或调用了 `global.js` 的 `trapFocus()`；两者皆无即 `Failed` |
| 静态 | `grep -n "trapFocus\|PopupBase" <file>` |
| 键盘 | 打开弹窗 → 连按 Tab 绕一圈，焦点**不得**跑到弹窗外的页面元素上 |
| 键盘 | `Esc` 能关闭 |
| 键盘 | 关闭后焦点**回到**打开它的那个按钮（不是回到 `<body>`） |
| 属性 | 弹层有 `role="dialog"` + `aria-modal="true"` + `aria-label` 或 `aria-labelledby` |
| 背景 | 打开时背景内容 `inert` 或 `aria-hidden="true"`，且页面锁滚动（用 `getScrollBarWidth` 补偿宽度防抖动） |

## 4. 轮播：button + aria-label

**判定对象**（`handoff-schema.md` §8.5）：轮播的翻页 / 分页控件是真 `<button>`，且各自有 `aria-label`。

| 判定 | 方法 |
|---|---|
| 结构 | 用 `{%- render 'section-swiper' -%}` 统一控件（见 `javascript-swiper.md` §5）——自建控件是主要失分点。⚠️ **用了 section-swiper 不等于 A11y 自动达标**，仍须查渲染后 DOM |
| 静态 | `.swiper-button-prev` / `.swiper-button-next` 的宿主标签**必须是 `<button>`** |
| 静态 | `.swiper-pagination` **是容器，可以不是 button**；真正要查的是 Swiper 运行时生成的 **bullet**——若 `clickable: true`，每个 bullet 必须可聚焦、可键盘操作、有可访问名 |
| 名称 | prev / next / 每个可点击 bullet 都有 `aria-label`（如 "Previous slide" / "Go to slide 3"），文案走 locales |
| 键盘 | Tab 能聚焦到 prev/next 并用 Enter/Space 翻页；bullet 可点则同样要能 Tab 到 |
| 状态 | 到头 / 到尾时禁用态用 `disabled` 或 `aria-disabled="true"`，不能只靠视觉变淡 |
| 自动播放 | 若有自动播放，须提供暂停方式，且 hover / focus 时暂停 |

## 5. 对比度 ≥ 4.5:1

**判定对象**（`handoff-schema.md` §8.5）：正文文字与其背景的对比度 ≥ **4.5:1**。

| 判定 | 方法 |
|---|---|
| 工具 | DevTools → 选中文本元素 → Styles 里的 color 色块 → Contrast ratio；或 Lighthouse Accessibility |
| 高风险组合 | `.text-tertiary`(#A3A3A3) / `.text-disabled`(#C7C7C7) 压在浅底（#F7F7F7 / #FFFFFF）上——**必查**，`#A3A3A3` on `#FFFFFF` 约 2.5:1，**只能用于非正文的辅助信息**，不得承载必读内容 |
| 高风险组合 | `.text-inverse-secondary`(#ABABAB) 压深底 |
| 配色方案 | 商家自定义方案色后对比度会变——**开方案态也要测一遍**，尤其重绑的 secondary / tertiary / surface（见 `colors-and-schemes.md` §5） |
| 图上文字 | 白字压图必须有遮罩 / 渐变兜底，抽样最亮区域测 |
| 记录 | QA 记录时写出**具体的前景/背景 hex + 计算出的比值**，不写"看起来没问题" |

色值表见 `colors-and-schemes.md` §2。

## 6. skip link

**判定对象**（`handoff-schema.md` §8.5）：页面提供"跳到主内容"链接，键盘用户不必逐个 Tab 过整个导航。

| 判定 | 方法 |
|---|---|
| 静态 | `grep -rn "skip" layout/theme.liquid snippets/header*.liquid` —— 找 `<a href="#MainContent">` 类元素 |
| 位置 | 必须是 DOM 里**第一个**可聚焦元素 |
| 行为 | 页面加载后按一次 Tab，skip link **必须可见**（默认视觉隐藏，`:focus` 时显现）；按 Enter 后焦点落到主内容容器 |
| 目标 | 目标容器存在且有对应 `id`，并有 `tabindex="-1"` 以便接收编程焦点 |

⚠️ 用 `display: none` / `visibility: hidden` 隐藏 skip link 会让它**永远无法聚焦**——必须用 clip / 位移方式做视觉隐藏。

## 7. focus-visible

**判定对象**（`handoff-schema.md` §8.5）：键盘聚焦时有清晰可见的焦点指示；不得全局清除 outline。

| 判定 | 方法 |
|---|---|
| 静态 | `grep -rn "outline: *none\|outline: *0" assets/ snippets/` —— 凡出现且未配套 `:focus-visible` 替代样式的，即 `Failed` |
| 手动 | Tab 遍历整个 section，每一步都要看得出焦点在哪 |
| 对比度 | 焦点环与相邻背景对比度 ≥ 3:1（**WCAG 2.1 通用要求，非 PLAUD spec 数值**；红线只要求"清晰可见"） |
| 范围 | 用 `:focus-visible` 而不是 `:focus`——鼠标点击不该出现焦点环，键盘必须出现 |
| 遮挡 | 焦点环不得被父级 `overflow: hidden` 裁掉（与"下拉不显示"同源问题，见 `javascript-swiper.md` §6） |

## 8. 附加检查（不在红线、非 PLAUD spec 数值）

> 本节来自 WCAG / 平台通用实践，**不是** PLAUD spec 定义的契约数值。QA 可作为改进建议提出，**不得**据此判 `A11yCheck: Failed`——红线只有 §1–§7 七项。

| 项 | 判定 |
|---|---|
| 图片 `alt` | 内容图有描述性 `alt`；纯装饰图 `alt=""`（不是省略 alt） |
| 标题层级 | 一页一个 `<h1>`，层级不跳级（h2 后不直接 h4） |
| 表单 label | 每个 input 有关联 `<label for>` 或 `aria-label`；错误提示用 `aria-describedby` 关联 |
| 语言标记 | `<html lang>` 随 Shopify locale 正确输出 |
| 动效 | 尊重 `prefers-reduced-motion`（自动轮播 / 视差 / 大幅动画） |
| 触控目标 | 交互元素触控区 ≥ 44×44 px（用 padding 撑，**不用固定宽高**——见 `handoff-schema.md` §8.2） |

---

## 9. QA 输出要求

`A11yCheck` 只能是 `Passed` / `Failed` / `Blocked`：

- 记 `Passed` 必须附**逐条的判定证据**（命令原文 + 输出摘要、或"Tab 遍历 N 个控件，焦点环均可见"这类可复核描述）；
- 无法预览 / 无法跑工具 → `Blocked` + 原因，**不得**猜"应该没问题"；
- 只写"已检查 A11y"不带证据的，按 `handoff-schema.md` §3「证据，不是声明」视为未执行。
